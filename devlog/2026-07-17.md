### 1. 홈 화면 재설계 — "밀렸어요" 배너 → 철학에 맞는 안내로 전환
당초 ROADMAP에 있던 "N일 밀렸어요 → AI가 다시 정리해드릴까요?" 배너 초안은, 밀림의
"실패해도 미뤄도 괜찮다, 대신 포기하지만 말아달라"는 서비스 철학과 어긋난다는 판단 하에
반려하고 재설계했다. 아티팩트로 6가지 시안(자리 유지/카드 배지/아이콘 배지/토스트/혼합형 등)을
실제 앱 스타일 그대로 재현해 비교한 뒤, "카드 배지 + 격려 카드"를 병행하는 혼합형으로 확정했다.

- 목표 카드에 "이어가는 중" 배지 (밀린 날이 있는 계획만, "밀렸다" 표현 없이)
- 격려 카드는 Solar 일일 메시지 표시 자리로 전환, 밀린 계획이 있으면 "이어가기" 버튼 노출
- 인사말 아래 "N일째 숲을 가꾸는 중이에요" — 리셋되지 않는 누적 공부일 카운터 (통계 페이지와 역할 분리: 통계=기록, 홈=감정)
- 복귀 환영 토스트 — 3일 이상 공백 후 첫 방문 시 6초간 표시 (`localStorage` 기반, DB 변경 없음)

### 2. Solar 일일 코치 메시지 (`milrim-coach` 신규 Edge Function)
매일 KST 자정에 pg_cron이 Solar를 1회 호출해 세그먼트별 메시지 16종을 일괄 생성·저장한다.
사용자별 호출이 아니라 "그날의 세그먼트별 공용 문구"라서, 가입자가 늘어도 Solar 호출량은
하루 1회로 고정된다.

- 세그먼트 판정(`src/lib/coach.ts`)은 브라우저가 본인 데이터로 계산: 유형(표준/꾸준·조금형/
  몰아침형) × 어제 달성률(4구간) 12종 + 워밍업·복귀(3일+ 공백)·마감임박(남은 하루 필요량이
  초기 계획의 2배 이상)·계획없음 4종
- Solar 생성 실패 시 코드 내장 폴백 문구로 대체되며, 이 경우 "AI 메이트" 배지를 숨겨 표기와
  구현이 어긋나지 않도록 함
- 사용자 피드백을 반영해 메시지 톤을 2차 조정: "내일부터 다시 시작해요" 류 표현 전면 금지
  (미루라고 부추기는 뉘앙스이므로), 번역체·사무적 어조·철 지난 유행어 금지 규칙을 프롬프트에
  명시. 6개 세그먼트 문구를 사용자 직접 작성안으로 교체하고 프롬프트 예시로 등록해 이후
  생성분도 같은 톤을 유지하도록 함
- SQL(`supabase/migrations/2026-07-16_daily_messages.sql`)·Edge Function 배포·수동 호출
  테스트까지 완료, 실제 생성 결과 확인 및 톤 보정 완료

### 4. 화면별 데이터 조회 범위 점검 — 관리자 계정 조회 정합성 개선
관리자 계정으로 로그인했을 때 "계획 상세에 일별 계획이 안 보인다"는 현상이 있어 원인을
살펴봤다. 확인해보니 데이터가 사라진 건 아니었다. `milrim_plans`의 관리자 전체 조회 RLS
정책 때문에 홈·계획 목록 등에서도 다른 계정의 계획이 함께 보이고 있었고, `milrim_plan_days`
에는 같은 정책이 없어 계획은 보이는데 그 안의 일별 계획은 안 보이는 비대칭이 생겼던 것으로
파악됐다. 이를 계기로 관리자에게 사용자별 상세 학습 계획까지 조회 권한을 줄지 검토했으나,
개인정보 보호를 우선해 조회 권한을 열지 않기로 결정했다.

- 원래는 전체 학습 계획을 한 화면에서 한 번에 보기 편하도록 목록 조회에 관리자 전체 조회
  정책을 열어뒀던 것인데, 이용자 수가 늘어날 것과 관리 편의성·UI 편의성을 고려해 **관리자
  모드에서 계정별 상세 조회를 할 때만 전체 데이터가 보이도록** 방향을 바꿨다
- 홈·계획 목록·계획 상세·통계 4개 화면의 조회 쿼리에 소유자 필터(`user_id`)를 명시적으로
  추가해, 관리자 계정에서도 일반 화면은 본인 데이터만 보이도록 정리
- 부수 개선: 관리자 페이지 "사용자 관리" 표의 학습 계획 개수를 클릭 가능한 링크로 만들어,
  계정별 학습 계획 목록(최근 생성순)을 조회하는 전용 페이지(`AdminUserPlansPage`) 신설.
  일별 계획·학습 기록은 열람 권한이 없어 표시하지 않음(개인정보 보호)

(`generate-plan`)과 상세 페이지의 수동 재분배 버튼에도 추가. 대회 심사 기준(AI 활용의 실제
구현 여부)에 맞춰 표기와 구현을 일치시키기 위함. 배포 이후 신규 생성 계획부터 기록되며,
