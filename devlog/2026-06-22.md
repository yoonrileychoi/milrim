### 2. 관리자 권한 보호 (`App.tsx`, `Sidebar.tsx`, `MyPage.tsx`, `AdminPage.tsx`)

**배경**
- 하드코딩 없이 Supabase Auth `app_metadata`에 `milrim_role: admin` 값을 부여하는 방식으로 관리자 계정 지정
- `app_metadata`는 서비스 롤 키 또는 Supabase 대시보드에서만 수정 가능 (유저 직접 수정 불가)
- Supabase SQL Editor에서 아래 쿼리로 설정:
  ```sql
  UPDATE auth.users
  SET raw_app_meta_data = raw_app_meta_data || '{"milrim_role": "admin"}'::jsonb
  WHERE id = (SELECT id FROM auth.users WHERE raw_user_meta_data->>'email' = '관리자이메일');
  ```

**App.tsx — AdminRoute 추가**
- `ProtectedRoute`(로그인 여부만 확인)와 별도로 `AdminRoute` 컴포넌트 추가
- `user.app_metadata.milrim_role !== 'admin'`이면 `/home`으로 리다이렉트
- `/admin` 라우트에 `AdminRoute` 적용

**Sidebar.tsx — 관리자 버튼 조건부 렌더링**
- `milrim_role: admin`인 경우에만 사이드바에 "관리자" 메뉴 표시

**MyPage.tsx — 관리자 모드 버튼 조건부 렌더링**
- `isAdmin`이 아니면 "관리자 모드" 버튼 미노출

**AdminPage.tsx — 페이지 내부 이중 보호**
- 라우트 보호를 우회하더라도 `isAdmin` 체크 후 잠금 화면 표시
- KPI 카드, 사용자 목록, 검색, 삭제 기능 모두 비관리자 접근 차단

### 3. 관리자 페이지 Supabase 실데이터 연동

**Supabase RLS 정책 (`app_metadata` 기반)**
- `milrim_profiles`, `milrim_plans`, `milrim_study_sessions` 테이블에 관리자 전체 조회 정책 추가
- 조건: `auth.jwt() -> 'app_metadata' ->> 'milrim_role' = 'admin'`

**AdminPage.tsx — 실데이터 연동**
- `milrim_profiles`: 전체 유저 목록 (닉네임, 가입일)
- `milrim_plans`: 유저별 플랜 수, 재계획 횟수
- `milrim_study_sessions`: 7일간 활성 사용자 수
- KPI 카드 실데이터 반영 (총 가입자, 7일간 활성 사용자, 누적 AI 재계획)
- 닉네임으로 검색 가능

**Edge Function: `admin-delete-user`**
- 호출자가 `app_metadata.milrim_role: admin`인지 검증 후 서비스 롤 키로 `auth.users` 삭제

**Edge Function: `admin-list-users` (신규)**
- `app_metadata.milrim_role: admin` 검증 후 서비스 롤 키로 전체 유저 목록(닉네임 + 이메일) 반환
- `milrim_profiles`(닉네임)와 `auth.users`(이메일) 서버에서 병합하여 응답

### 5. 닉네임 저장 버그 수정 (`AuthContext.tsx`, `ProfilePage.tsx`, `MyPage.tsx`, `Sidebar.tsx`)

**원인**
- 기존 방식: `supabase.auth.updateUser({ data: { name } })`로 `user_metadata`에 저장
- Kakao OAuth 로그인 시마다 Supabase가 Kakao 사용자 정보로 `user_metadata`를 덮어써 닉네임이 초기화됨

**수정 방식**
- `ProfilePage.tsx`: `milrim_profiles` 테이블에 `upsert`로 저장 (`id`, `nickname`)
- `AuthContext.tsx`: 로그인·세션 변경 시 `milrim_profiles`에서 `nickname` 조회, 컨텍스트에 `nickname` 상태 추가
- `MyPage.tsx`, `Sidebar.tsx`: `user_metadata` 대신 컨텍스트의 `nickname` 우선 사용
